Declare an agent once. Apply it wherever it can run.

Solaria plans and applies AI agent definitions across hosts, and records what it deployed where. The host runs the agent loop. Solaria defines, deploys and tracks.

The card stays put. Targets decide where it runs.

reviewer is one card: instructions, model, tools, skills and limits. It names no host. Three targets place it in a local container, on Managed Agents with tools on your machine, and fully in Anthropic's cloud.

Open a host to see what it changes. local-gitagent swaps the model for Haiku, so only its digest moves.

kind: Agent
metadata: {name: reviewer}
spec:
  description: Reviews a change and flags risky edits
  model: {preferred: anthropic:claude-sonnet-5-5}
  tools:
    builtin: [shell, read]
    mcp: [{ref: deepwiki}]
  skills: [skills/review-rubric]

Agents do the work. These rules keep it honest.

  1. First law

    A plan never surprises you.

    solaria plan diffs every field against recorded state before any host is called.

  2. Second law

    An agent keeps one identity on every host.

    State records which agent, with which content digest, runs where. The digest moves only when the card, or a target's override, changes. solaria.lock pins it per target, for review in git.

  3. Third law

    What a host can't run never reaches it.

    Capability checks fail the plan early and name the field. Smaller gaps come back as warnings, like limits a host doesn't enforce.

Hosts today

A provider is the code that talks to one kind of host. Each one declares what it can run, so a card a host can't take fails at plan time, not halfway through an apply.

Install Solaria

One binary with nothing else to install. Pick your system.

The scripts download the latest release from GitHub, check its SHA-256 checksum, and install the binary for your user, without sudo. Releases are also signed with cosign. To install by hand, download an archive from the releases page.

With Homebrew

brew install solaria-sh/tap/solaria

Or with the install script

curl -fsSL https://solaria.sh/install.sh | sh

The script installs to ~/.local/bin. Set SOLARIA_INSTALL_DIR to choose another folder.

With the install script

curl -fsSL https://solaria.sh/install.sh | sh

Works on amd64 and arm64. It installs to ~/.local/bin; set SOLARIA_INSTALL_DIR to choose another folder.

Or run the container image

docker run --rm ghcr.io/solaria-sh/solaria version

In PowerShell

irm https://solaria.sh/install.ps1 | iex

Installs to %LOCALAPPDATA%\Programs\Solaria and adds it to your user PATH. Open a new terminal afterwards.

Then check it

solaria version
