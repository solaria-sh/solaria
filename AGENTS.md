# AGENTS.md

Guidance for AI coding agents working in this repository. People should start with [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## Project

Solaria is a Go CLI that plans and applies agent definitions across hosts, Terraform-style. It is a control plane: it never runs an agent loop itself (see [ADR 0002](docs/adr/0002-control-plane-not-agent-framework.md)). Read the ADRs in `docs/adr/` before changing anything structural. They are the source of truth for the design.

## Commands

```bash
make build     # bin/solaria
make test      # go test -race ./...
make lint      # golangci-lint
make schema    # regenerate schemas/ after changing internal/api
make check     # everything CI runs; run this before you finish
```

To update expected output after an intended change, run `go test ./... -update` and review the diff. CLI behavior is tested with [testscript](https://pkg.go.dev/github.com/rogpeppe/go-internal/testscript) scripts in `internal/cli/testdata/script/`; add a script there for any new command or diagnostic.

## Layout

- `cmd/solaria/`: the entry point only. No logic here.
- `internal/cli/`: cobra commands. Keep them thin; they call into the engine.
- `internal/api/v1alpha1/`: resource types (Agent, Environment, McpServer, Vault). These are the source of truth for the JSON Schema in `schemas/`. Field doc comments become schema descriptions, so write them for people editing agent definitions.
- `internal/scaffold/`: the templates `solaria init` writes, embedded from `internal/scaffold/templates/<name>/`, and fetching git templates. `internal/cli/testdata/script/init*.txtar` validates and plans each embedded template, so a template can't fall behind the schema (ADR 0015).
- `internal/schemagen/`: generates `schemas/v1alpha1/*.json` from the types. A test fails when the committed files are stale.
- `internal/config/`: finds YAML files, checks each document against its schema, and decodes it. Errors carry file, line and column.
- `internal/validate/`: checks across resources (references, files on disk, skills, portability warnings).
- `internal/diag/`: diagnostics shared by all of the above.
- `internal/resolve/`: applies environment overrides and references, reads instruction and skill files, and builds the `Definition` that providers render and digests hash.
- `internal/digest/`: RFC 8785 canonical JSON and SHA-256.
- `internal/provider/`: the provider interface, plans and field diffs. `internal/providers/<name>/` holds the implementations; `internal/providers/stub/` is the file-backed test provider used by examples and end-to-end tests. `internal/providers/gitagent/` builds container images; its golden files are in `testdata/*.golden` (`go test ./internal/providers/gitagent -update`), and `SOLARIA_IT_DOCKER=1` runs its integration test against real Docker. `internal/providers/managedagents/` calls the Managed Agents API through the Go SDK; its tests run the engine against a fake API (`httptest`) and compare every request with `testdata/*.golden`. `SOLARIA_IT_MANAGED_AGENTS=1` creates real objects; never run it without the maintainer's go-ahead. `internal/providers/claudeagentsdk/` renders a launcher bundle for the `process` placement, or builds it into an image for `docker`; its golden files are in `testdata/*.golden` (`go test ./internal/providers/claudeagentsdk -update`). `internal/providers/process/` holds the `process` placement's shared isolation: the launcher preludes, the machine's Claude Code managed settings, which it can't keep out, and the srt settings for `sandbox.isolation: srt` (`SOLARIA_IT_SRT=1` runs a shell inside the real srt). `internal/providers/container/` holds the docker CLI wrapper and sandbox base the container providers share.
- `internal/engine/`: refresh, plan, capability checks, apply and plan rendering. `internal/state/`: the state format and the local backend with its lock.
- `examples/`: runnable projects, copied into the end-to-end scripts. `examples/hello` uses the stub provider; `examples/reviewer` is the v0 success test, one agent in three environments.
- `docs/adr/`: architecture decisions. `docs/spikes/`: research notes that feed them.
- `docs/resources/` is generated by `make schema`, like `schemas/`, one page per kind; a test fails when it's stale. `docs/concepts.md`, `docs/getting-started.md` and `docs/providers/` are written by hand and must follow behavior changes.
- `site/`: the solaria.sh website, its own Go module. It renders the landing page and every page of `docs/` with the design system in `site/DESIGN.md`. `make site-serve` previews it; `make site-test` checks every link. A new page under `docs/` must be added to the page list in `site/main.go`. The build also copies `schemas/` to solaria.sh/schemas/, the URLs the schemas' `$id`s name. `.github/workflows/site.yml` deploys it to Cloudflare Pages (see CONTRIBUTING.md); `site/static/_headers` sets its response headers.
- `.goreleaser.yaml` and `.github/workflows/release.yml` build releases. `make release-check` validates the config and `make release-snapshot` builds one locally. `.github/workflows/release-please.yml` (with `release-please-config.json` and `.release-please-manifest.json`) keeps a release pull request open on `main` and writes `CHANGELOG.md` from Conventional Commits, so don't edit the changelog by hand; merging that pull request tags the release. Never merge the release pull request, tag, or publish a release without the maintainer.

Everything is under `internal/` until the API stabilizes. Don't add public packages without an ADR. The one exception is `schemas/`, which only embeds the published schema files (`go:embed` can't reach them from `internal/`).

## Conventions

- Standard Go style; `gofumpt` and `goimports` formatting, enforced by the linter.
- Wrap errors with context (`fmt.Errorf("load %s: %w", path, err)`). Never panic on user input.
- User-facing errors name the file and field so the problem can be fixed.
- Unit tests must not use the network, Docker or real credentials. Use fakes (`httptest`, interface fakes). Integration tests are opt-in through `SOLARIA_IT_*` environment variables.
- Secrets never reach state, digests, logs, plan output or rendered files. Only the names of secret references do.
- Anything that changes `resolve.Definition` or its normalization changes every digest. Bump `resolve.Format`, update ADR 0008, and only then regenerate the golden files. The exception is a new field omitted when empty (`omitempty`), which leaves existing digests alone; it still needs a line in ADR 0008.
- Conventional Commits, signed off (`git commit -s`).
- A change to an architectural decision needs an updated or new ADR in the same pull request.
